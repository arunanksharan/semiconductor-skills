# Semiconductor Skills for Claude Code

Agent Skills that give Claude Code real working judgment in **semiconductor
manufacturing** — yield monitoring, failure analysis, package qualification, and
fab process engineering.

As of August 2026 a search of every public `SKILL.md` on GitHub found no skill
covering wafer-fab process engineering, packaging/OSAT qualification, or yield
monitoring, and exactly one covering failure analysis. This repo fills that gap.

Built by [Kuzushi Labs](https://github.com/arunanksharan). MIT licensed.

## The skills

| Skill | What it does | Use it when |
|---|---|---|
| [`semi-yield-monitor`](skills/semi-yield-monitor) | Yield triage: bin paretos, wafer-map spatial signatures → likely cause, defect-density models (Poisson/Murphy/Seeds/negative-binomial), lot·tool·time commonality, SPC on yield | A lot comes back low-yield and you need to know *where* to look |
| [`semi-failure-analysis`](skills/semi-failure-analysis) | Structured FA: symptom intake → mechanism taxonomy (EOS/ESD, EM, TDDB, HCI, NBTI, package modes) → hypothesis table → cost-ordered technique plan with **hard gates before destructive steps** → 8D report | An RMA, customer return, or bin signature needs a root cause |
| [`semi-packaging-qual`](skills/semi-packaging-qual) | Package qual plans from JEDEC-style flows (precon/MSL, TC, HAST/uHAST, HTSL, THB), assembly-step defect catalog, MSL advisor, LTPD sample sizing | Qualifying a package for consumer, industrial, or AEC-Q100 automotive |
| [`semi-fab-process`](skills/semi-fab-process) | Excursion triage runbook (**metrology-verification gate first**), per-module failure modes (litho/etch/dep/implant/CMP), DOE builder + analyzer, chamber matching, SPC/FDC | An inline parameter goes out of control and you must scope, hold, and root-cause it |

Each skill is three layers: `SKILL.md` (the decision procedure), `references/`
(domain depth, loaded on demand), `scripts/` (deterministic Python — the model
chooses the analysis, Python computes the numbers).

## Install

```bash
git clone https://github.com/arunanksharan/semiconductor-skills.git
cd semiconductor-skills
# install all four for your user
for s in skills/*/; do ln -s "$PWD/$s" ~/.claude/skills/$(basename "$s"); done
# python deps (per skill; numpy/pandas/matplotlib/scipy only)
pip install -r skills/semi-yield-monitor/requirements.txt
```

Then just describe the problem — Claude Code loads the right skill from your
wording ("this lot came back at 62% yield, here's the bin data").

Works with any agent that reads the `SKILL.md` convention (Claude Code, and
other agent runtimes that adopted the format).

## Design rules

1. **Encode judgment, not textbook prose.** Value lives in decision procedures,
   discriminating-evidence tables, and ordered workflows with stop-gates.
2. **Numbers come from scripts, never from the model.**
3. **Destructive and expensive steps are gated** — FA cannot jump to decap or
   FIB before the non-destructive evidence is logged; fab triage cannot call a
   hold before metrology is verified.
4. **Degrade honestly.** With no data the skills interview you and produce a
   plan; they never invent numbers.
5. **Public sources only.** Concepts are written from scratch and standards are
   cited by number/clause — no proprietary recipes, no reproduced standard text.

## Scope and honesty

These skills carry **methodology**, not any fab's process-of-record. Recipe- and
tool-specific best-known-methods are proprietary by nature and belong in a
private fork alongside your own data. The `semi-fab-process` skill states this
boundary explicitly.

Sample data is synthetic and generated by the included scripts. Evals and their
actual measured results live in [`evals/`](evals).
